# Claude Design — import package

A self-contained bundle to hand to **Claude Design** (Anthropic Labs, research
preview, Opus 4.7) during design-system onboarding. Claude Design has **no
proprietary import format** — onboarding just reads code, design files, and
documents, then extracts colors, typography, components, and spacing. The only
proprietary format is the *reverse* handoff bundle (Claude Design → Claude
Code), which is generated by Claude Design and cannot be authored by hand.

This folder is the curated entry point so you can point Claude Design at a
focused subdirectory instead of the whole monorepo (the docs warn that linking
large repos causes lag).

## What's in here

| File | Role | Does Claude Design ingest it? |
|---|---|---|
| `design-system-brief.md` | **Index** to the canonical design system (in `frontend-core`) + a cockpit-skin appendix | Optional fallback seed — the real target is `frontend-core/contract/` |
| `CONNECTION.md` | How Claude Design connects to this fleet (findings + caveats) | No — human/Claude Code reference |
| `README.md` | This file | No |

> **The canonical Untool.ai design system lives in the `frontend-core` spoke**
> (W3C DTCG `contract/design-tokens.json`, `theme.json`, `icons.json`,
> per-component `*.api.ts`, and `.figma/` Code Connect) — **not** in this hub
> repo. Onboard Claude Design against that, not the cockpit theme. See
> `design-system-brief.md` for the artifact map.

## How to onboard Claude Design with this package

Claude Design accepts these inputs during design-system setup:

- **GitHub repo URL** — reads components, architecture, styling patterns.
- **Local code folder** — drag a folder in; it copies selected files rather
  than uploading the whole repo.
- **Figma `.fig`** — parsed locally in the browser, never uploaded to Anthropic.
- **Documents** — DOCX, PPTX, XLSX, PDF, images, plus individual assets (logos,
  palette files, type specimens).

It extracts: color palette (primary/secondary/accent hex), typography
(families, sizes, weights), components (buttons, cards, nav), and layout
patterns (spacing, grid, page structure).

### Recommended entry points (most → least authoritative)

1. **`frontend-core/contract/`** (the spoke's contract subdirectory) — the
   canonical design system: W3C DTCG `design-tokens.json`, `theme.json`
   (light/dark/branded), `icons.json`, per-component `*.api.ts`, plus `.figma/`
   Code Connect. Small and focused — point Claude Design's GitHub-URL onboarding
   here. This is the real Untool.ai design system.
2. **`design/claude-design-import/design-system-brief.md`** (this package) — an
   index to the above plus a fallback seed; use only if you can't point Claude
   Design at `frontend-core` directly. It maps the artifacts but does not carry
   their token values.
3. **`extensions/arcadedb-cockpit/public/styles.css`** — internal operator
   console skin (dark/neon). A code sample of an internal tool, **not** the
   product design system.

> Do **not** point Claude Design at the AgentArmy hub root — it's a template /
> orchestration repo with almost no UI, so extraction would be noisy.

## Direction matters

- **Repo → Claude Design (import):** code + docs + assets, as above. Nothing
  proprietary; just give it focused sources.
- **Claude Design → Claude Code (handoff):** Claude Design packages the
  component structure as a machine-readable spec, the design tokens used on the
  canvas, the layout hierarchy, and referenced assets into a proprietary
  handoff bundle. Generate it in Claude Design, then hand it to Claude Code.
- **Figma:** Claude Design ingests Figma `.fig` on the way *in* but has **no
  Figma export**. A round-trip back to Figma needs a third-party path (e.g.
  Anima) or the read-only Figma plugin for Claude Code.
