# 🧩 OOP Patterns for Agentic Platforms

> [!abstract] Why this track exists
> Agentic systems generate change pressure. OOP is how we keep that pressure from turning into spaghetti: **stable objects, explicit boundaries, evidence-first invariants**.

**🎛 [[Obsidian Board]] · 🧭 [[Platform Atlas]] · 🏷️ [[Taxonomy]]**

## Start here

- [[Evidence-Backed Aggregates]] — aggregates whose state is “what evidence proves”
- [[Policy Objects]] — policy as data; governance that composes
- [[Scenario Objects]] — scenarios as first-class objects (capabilities that prove themselves)

## What good looks like

- Objects have **names that match ontology concepts**, not storage jargon (see [[Middle-Core]]).
- Changes route through **scenarios** that emit evidence (see [[Agentic Loop Primitives]]).
- Boundaries make regeneration safe (see [[Codegen vs Interpreted]]).
